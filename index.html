See the tokens Claude Code and Codex load before you type.

Every session starts with your whole setup: every MCP tool name, every skill, every hook's text, CLAUDE.md and AGENTS.md. packlight measures it from your own session logs, shows what you never use, and archives it in one step. Undo anytime.

See a sample report Open source on GitHub

Free and MIT licensed. Runs on your computer and sends nothing anywhere. macOS, Linux and Windows.

What packlight shows you

Tokens per session

How much of the context window your setup takes before you type, split by source. For Codex the number is measured: Codex logs each session's input tokens.

MCP servers

Each server's tool names and instructions, which load every session whether you call them or not, and how often you actually do.

Skills and plugins

Which skills you used, which you never did, and which Claude Code dropped from its skill listing because it ran out of room.

Hooks

The text each hook adds to your sessions and how long it takes to run.

One-click fix

Archives everything unused since it was installed, after one question. Items only you can remove (claude.ai connectors, app plugins, Codex config) come with the exact place to do it.

Try it on your setup

  1. Install it. Needs Node 20 or later.

    git clone https://github.com/cooperism-lab/packlight
cd packlight
npm install && npm run build && npm link

  2. Scan and open your report.

    packlight                 # Claude Code
packlight --agent codex   # Codex

  3. Archive what you don't use. It shows the plan and asks once. Everything can be put back.

    packlight fix
packlight restore --all   # undo

Questions

Why does my Claude Code context fill up before I type anything?

Every session starts with your whole setup: the name of every MCP tool, a listing of every skill, the text your hooks add, agent descriptions and CLAUDE.md files. packlight measures each part from your local session logs, so you can see which part is biggest.

How many tokens do MCP servers use?

Claude Code names every MCP tool at the start of each session, and some servers add instructions. A server with 200 tools can cost over 3,000 tokens per session even if you never call it. packlight shows each server's cost and how often you used it.

Does it work with Codex?

Yes. For Codex, packlight reads the input tokens Codex logs for each session's first request, so the headline is measured rather than estimated. Codex plugins and MCP servers are switched off in ~/.codex/config.toml; packlight shows you the exact line.

Is it safe? Can I undo it?

packlight asks before changing anything, moves items into an archive instead of deleting them, and restores them byte for byte with one command. It never edits CLAUDE.md or AGENTS.md, and it runs offline.

How is this different from /context?

Claude Code's /context shows what one session holds right now. packlight looks across all your sessions to find what you never use, then removes it safely and can put it back.
